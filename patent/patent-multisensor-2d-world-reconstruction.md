# 台球第一视角多源数据2D映射算法

> 本文目标是把眼镜第一视角中不断变化、可能漏检或误检的图像观测，转换为相机视角无关、以毫米表示并可跨帧保持的二维球桌世界状态。本文不展开击球策略、界面设计和大模型功能。

## 一、输入、输出与处理关系

系统使用以下数据：

- 视频帧及视频时间戳；
- 球桌分割多边形；
- 球、角袋、中袋和架杆手的检测类别、置信度及包围框；
- 球杆关键点；
- Android Rotation Vector 输出的四元数及传感器时间戳；
- 相邻视频帧的稀疏光流。

当前姿态协议还允许携带 `position_m`、`tracking_state` 和 `coordinate_frame`，但当前代码只把可选平移量记录为运动诊断数据，没有直接使用六自由度平移计算球桌坐标。当前二维映射的绝对坐标来源仍是球桌、袋口和已确认静止球；四元数与光流用于判断相机运动，防止头部运动污染世界状态。

系统输出两个不同层次的数据：

```text
ObservedState_t：当前帧真实看到的球及其二维投影
WorldState_v：多帧确认并跨视角保持的二维球局
```

`ObservedState_t` 可以因遮挡或视野变化而缺球。`WorldState_v` 是策略和眼镜显示使用的物理状态，不能因一帧漏检立即删除球，也不能由无检测依据的跟踪预测框更新。

整体处理关系为：

```text
视频帧
  -> 球桌分割 + 球/袋口检测
  -> 当前帧检测过滤
  -> 袋口单应映射 / 静止球锚点恢复 / 短时映射缓存
  -> 球接触点投影到规范球桌毫米坐标
  -> 光流 + 四元数判断相机运动和球运动
  -> 多帧观测一致性检查
  -> 提交或维持二维 WorldState
```

## 二、二维映射与世界状态维护算法

**1. 建立规范球桌坐标系**

当前实现把球桌定义为 `2540 mm x 1270 mm` 的矩形，坐标原点位于规范俯视图左上角。四个角袋和两个中袋的坐标固定为：

```text
(0,0), (1270,0), (2540,0),
(0,1270), (1270,1270), (2540,1270)
```

标准球半径为 `28.575 mm`。后续球位、位移、碰撞点和策略路线统一使用该物理坐标系，不直接使用图像像素坐标。

**2. 形成当前帧可信观测**

球桌分割模型每帧运行。分割掩膜使用指数平滑，再提取最大连通轮廓作为当前球桌多边形。

检测器输出球、袋口和架杆手。内部短时 track 用于类别投票和重新关联，但稳定模式遵循 detection-first 原则：

- 新 track 默认需要连续三帧检测才确认；
- 类别由滑动窗口内的检测置信度加权投票确定；
- 同一球号只保留证据较强的一个观测；
- 球中心明显位于球桌多边形外时丢弃；
- 当前帧没有 detection 时，track 可在内部短时保留，但不输出预测框；
- `coasting` 或速度外推框不参与二维映射。

球的投影点取包围框底边中点：

```text
p_img = ((x1+x2)/2, y2)
```

该点近似为球与台呢的接触点，比包围框中心更符合平面单应映射假设。

**3. 通过袋口建立图像到球桌的单应矩阵**

设图像点为 `p=[x,y,1]^T`，球桌点为 `P=[X,Y,1]^T`，系统使用 `3x3` 单应矩阵 `H_t`：

```text
[u,v,s]^T = H_t [x,y,1]^T
X = u/s
Y = v/s
```

当前主建系方式使用袋口自然锚点：

1. 从球桌多边形附近选取置信度较高的角袋和中袋，最多四个角袋、两个中袋；
2. 角袋只与规范角袋排列匹配，中袋只与规范中袋排列匹配；
3. 枚举可能的一一对应关系，并为每种关系计算候选 `H_j`；
4. 将当前球桌多边形经 `H_j` 投影，与规范矩形计算 IoU；
5. IoU 小于 `0.55` 的候选直接拒绝；
6. 当锚点不少于五个时，平均重投影误差超过 `30 mm` 的候选拒绝；
7. 检查规范球桌角点相对当前可见桌面的外推范围，区分 `global` 和 `local` 映射；
8. 至少检测到四个袋口且候选属于全局映射时，才能建立或刷新 `world lock`。

多个候选同时通过几何门槛时，系统继续比较其时间一致性。对候选 `H_j`，将当前公共球投影到球桌坐标，与前一帧或已有锚点比较：

```text
drift(H_j) = median ||project(H_j, p_i,t) - P_i,reference||
```

系统先保留桌面 IoU 接近最优的候选，再优先选择 `drift` 较小的候选。若公共球不足，则比较当前袋口在上一矩阵与候选矩阵下的锚点漂移。系统还计算映射局部手性，并在规范坐标中统一镜像方向，避免球桌对称结构导致映射在相邻帧左右翻转。

**4. 袋口不可见时恢复或短时维持映射**

首次获得可信全局映射后，系统保存当前静止球的图像标识、类别和球桌毫米坐标。后续袋口不足时，可以用已确认静止球恢复映射：

1. 按内部 track 标识或球类别寻找当前图像球与历史球桌坐标的对应；
2. 至少四组对应点才进行估计；
3. 使用 RANSAC 计算单应矩阵，物理重投影阈值为 `35 mm`；
4. 要求至少四个内点，内点比例不低于 `0.55`；
5. 锚点覆盖面积不低于当前桌面图像面积的 `2%`；
6. 再检查桌面 IoU、映射范围和方向手性。

如果当前帧既不能通过袋口更新，也不能通过静止球恢复，则有限时间复用最近可信 `H`，默认最长约三秒。缓存矩阵持续接受以下检查：

- 当前球桌多边形与规范桌面不再匹配时立即失效；
- 非击球阶段，新映射使公共球中位跳变超过 `120 mm` 时拒绝新映射；
- 使用缓存时，公共球在球桌坐标中的中位漂移连续三帧超过 `25 mm` 时废弃缓存；
- 超过 world lock 有效期后，即使仍有局部矩阵，也不能作为全局策略坐标。

因此，`H` 存在不代表映射可靠。只有同时满足以下条件才产生可提交的全局二维观测：

```text
H_t != null
and coord_scope == global
and world_locked == true
```

**5. 投影球位并过滤异常坐标**

对当前帧每个具有真实 detection 的球，将其底边中点通过 `H_t` 投影。投影结果只有位于规范球桌边界外扩 `60 mm` 范围内才保留：

```text
-60 <= X <= 2600
-60 <= Y <= 1330
```

得到当前帧二维观测：

```text
Z_t = {ball_class -> [X_mm,Y_mm]}
```

该集合仍只是当前观测，不直接覆盖世界状态。

**6. 使用光流和姿态区分相机运动与球运动**

系统在球桌区域内提取最多约 120 个角点，并从光流掩膜中排除球框及其邻域。使用稀疏 Lucas-Kanade 光流计算相邻帧点对应，再用 RANSAC 估计全局二维仿射变换 `A_t`。

全局运动可信条件包括：有效点不少于 12 个、RANSAC 内点比例不低于 `0.6`、空间覆盖率不低于 `0.08`、中位重投影误差不超过 `2.5 px`。与视频时间戳相差不超过 `100 ms` 的四元数用于检查相邻帧姿态变化和运动数据时效。

对短时关联到的球，计算扣除全局图像运动后的残差：

```text
r_i,t = ||c_i,t - A_t [c_i,t-1,1]^T||
```

当全局运动幅度不低于 `2 px`、全局运动估计可信、存在球残差且球残差中位数不超过 `2.5 px` 时，当前帧标记为 `camera_only`。这种帧不推动击球状态，也不使用相机运动造成的表观球位变化更新物理世界。

当全局运动估计可信，且球残差最大值不低于 `4 px` 时，产生 `object_motion_confident`。进入击球状态还要求球桌毫米坐标中同时存在球位移，并连续两帧满足条件。四元数或可选位置数据只提供相机运动辅助，不能单独确认某颗球存在或发生移动。

**7. 以多帧非对称规则维护 WorldState**

设当前二维观测为 `Z_t`，已提交世界为 `S_v`，公共球集合为 `C`。系统计算：

```text
common_ratio = |C| / max(1, min(|Z_t|, |S_v|))
distance = median_i_in_C ||Z_t(i)-S_v(i)||
```

当 `common_ratio >= 0.5` 且 `distance <= 70 mm` 时，两次观测被认为属于同一球局。

世界状态按以下规则维护：

- 尚无世界状态时进入 `STABILIZING`，连续三帧候选相容后提交首个世界版本；
- 候选和已存在球的位置使用 EMA 融合，当前权重 `alpha=0.25`；
- 稳定世界中的已有球只有在当前帧重新检测并映射可信时才更新位置；
- 新球号在与当前世界相容的有效帧中累计获得三次正观测后才加入；
- 局部第一视角中没有看到某颗球，不作为删除该球的证据；
- 映射失效时保留上一个世界，但阶段标记为 `DEGRADED`，不能冒充当前可靠观测；
- 检测到真实击球运动时进入 `MOVING`，保留击球前世界并积累新候选；
- 球重新稳定且候选满足约五帧相容要求后，提交击球后的新世界；
- 没有击球证据却出现整体大幅变化时，需要更严格的 60 帧候选确认，防止误映射或错分类替换整桌状态。

该规则对新增和删除采用不同证据标准：看到新球需要重复正证据；暂时未看到旧球不代表其消失。这样用户站在一个位置逐步扫描球桌时，不同帧看到的局部球集合可以融合到同一个二维世界中。

**8. 世界状态和映射状态分别版本化**

系统输出三个独立状态量：

- `mapping_revision`：接受新的相机到球桌映射时更新；
- `world_revision`：正式提交新的球局物理状态时更新；
- `epoch`：`IDLE/AIMING/SHOT/SETTLED` 行为阶段变化时更新。

头部移动通常只改变映射版本，不应改变世界版本。单帧漏检不改变正式世界。策略只读取 `world_phase=STABLE` 的世界状态，并绑定对应 `world_revision`，从而避免使用过期或不可靠的二维球位。

逐帧算法可概括为：

```text
输入：帧 I_t、时间戳 tau_t、姿态队列 Q、上一映射 H、上一世界 S_v

1. 执行球桌分割、球/袋口检测和球杆检测
2. 过滤非当前帧 detection、桌外目标和未确认的新 track
3. 用非球区域光流估计全局相机运动，并对齐最近四元数
4. 优先由袋口组合计算 H_t；失败时尝试静止球锚点；再次失败时检查有限缓存
5. 校验 H_t 的 IoU、重投影误差、范围、手性和跨帧漂移
6. 将真实球检测投影为当前毫米坐标观测 Z_t
7. 根据全局运动和球残差判断 camera_only 或 object_motion
8. camera_only 时不推进物理运动；其余情况按多帧相容性更新候选
9. 候选满足对应门槛时提交 WorldState，并更新 world_revision
10. 输出当前观测、映射质量、运动类型和版本化二维世界
```

## 三、总结

当前2D映射算法通过袋口和静止球建立统一的球桌物理坐标，把不同视角下的真实检测融合为一个多帧二维世界；光流和姿态负责解释相机运动，世界状态机负责判断观测何时足以成为物理事实。
